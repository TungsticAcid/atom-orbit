# 原子轨道三维可视化 · Hydrogen-like Atomic Orbital Visualizer

一个**移动端友好、可离线运行**的交互式 H5 工具，用三维图形直观展示**类氢原子波函数**（核电荷数 `Z` 可在 **1–36** 之间调节，H → Kr³⁵⁺；类氢与氢只差一条标度关系 `r → r/Z`、`E ∝ Z²/n²`），帮助学生/教育工作者理解抽象的量子力学概念。

## ✨ 功能特性

- **顶栏右上角显示"当前正在看的那个数学对象的符号"**：球谐档写 `Y`（如 `Y_{1-1}`；实解档维持轨道名 `Y_{p_z}`），波函数档写 `ψ`（实解档 `ψ_{3d_{z²}}` 多级下标、复解档 `ψ_{322}` 连写）。旁边的徽标同步写"球谐 / **空间波函数** · 实数解 / 复数解"——与面板上那个按钮**逐字一致**。
  > 这里原先显示的是**轨道名**（`3d_z²`），而三维里画的可能是 `Y`、也可能是 `ψ` —— 名字没交代"看的是哪个量"，于是出现"三维里画的是 Y、顶栏却写 3p_z"这种图文不符。符号由 `formula.js` 的 `symbolHtml()` **独家**构造（此前散在三处，改一处漏两处）。
  > 顶栏字体是 Georgia，排版上补了一条 `font-variant-numeric: lining-nums`：Georgia 的**旧式数字**（old-style figures）字形只有 x 高度那么高、还沉到基线以下，`3d` 里的数字看着只有字母的一半；换成 lining 数字后与字母同坐基线（实测墨迹底边由基线下 13px 抬到 1px）。
- **量子数控制**：滑块与**数字输入框**双通道调节主量子数 `n`（1–6）、角量子数 `l`，以及**实轨道**逐项选择（实数解档按化学名给按钮 `p_z / p_x / p_y`、`d_z² / d_xz / …`），实时联动（l 上限随 n、m 范围随 l 自动收窄）；输入框会校验类型与范围，非法值标红提示且不改变状态。
- **核电荷数 `Z`**（1–36）收在面板顶部的**折叠区**里（默认 `Z = 1` 氢）——摊开会占掉一大块，而多数教学场景用不到它。折叠后**标题仍带当前值**（`▸ 核电荷数 Z = 1`）：`Z` 会静默改掉所有尺度与能级（`r → r/Z`、`E ∝ Z²`），标题不写出来，学生改过再折回去就想不起来画面为什么变了。
- **三维视图有两个档位**（面板「视图对象」切换：**球谐函数 / 空间波函数**）——共用同一个三维窗口与同一套相机/操作（旋转/缩放/平移/自动旋转/复位），但底层是**两套几何**：
  - **球谐函数**（角度部分 `Y`）：极坐标曲面 `r = |Y|` 或 `|Y|²`，解析形状直接三角化。着色由判据派生（见下「三维着色」那条）：实数解取 `|Y|` 时按 `sign(Y)` 分 ±红/青，取 `|Y|²` 时纯色；复数解一律纯色。**曲面与波函数等值面共用同一套光照材质**（`MeshStandardMaterial` + 顶点法线），所以有明确的高光与明暗梯度、一眼能看出哪一瓣朝向观察者。**p_z 画出来就是两个相切的球面**；它只依赖 `l`、`m`、**与 `n` 无关**——切 n 时曲面纹丝不动，这正是"2p_z 与 3p_z 角度分布相同"的可视化证据。
  - **空间波函数**（完整 ψ）：按概率密度 `|ψ|²` 实时生成（**默认等值面**，判据取 `|ψ|²` 时可切电子云）。
  - **电子云**：按 `|ψ|²` 重要性采样数万个点，统计上即真实电子分布。
    > ★ **「三维渲染」（电子云 / 等值面）整组只在判据取 `|ψ|²` 时出现**：电子云就是按 `|ψ|²` 采样出的点云，这个概念依附于 `|ψ|²`。判据取 `ψ` 时没有电子云可言 —— 程序会把渲染方式**拉回等值面**并把那一组控件收起（控件本身也切过去，免得 DOM 显示"电子云"而画面画的是等值面）。
  - **等值面**：在网格上走四面体行进（marching tetrahedra）提取等值面，**判据可切换 `|ψ|²` / `ψ`**（实数解档写作 `ψ`，不带绝对值竖线——实函数本身带符号，那个竖线是多余的；复数解档写作 `|ψ|`，因为复函数的非平方判据就是模），阈值可调；经顶点焊接 + Taubin 平滑 + 一致朝外绕向处理，表面光滑。**着色也由判据决定**（见下）。
    > `|ψ| = c` 与 `|ψ|² = c²` 是同一族曲面，故切换判据**改变的是读数的含义而非形状**：同一读数 `f`，按 `|ψ|²` 计为 `f·|ψ|²max`，按 `|ψ|` 计等价于 `f²·|ψ|²max`（`f<1` 时更小）→ 得到**更大**的表面。面板会实时显示两者的换算，如 `30.0% |ψ|² ⟺ 54.8% |ψ|`。
  - 网格范围随阈值自适应（收紧到等值面实际外延，而非波函数渐近尾部），同分辨率下格距可细数倍——这是分辨 p 轨道节面附近两瓣窄缝的关键。
  - 阈值滑块为**对数刻度**、覆盖 `0.3%–80%`（线性刻度下低端拖不到；取对数刻度就要看中点落在哪 —— `0.3%×80%` 的几何平均是 **4.9%**，正好落在常用轨道推荐值附近，而原量程 `0.02%–80%` 的中点是 1.26%）；面板按当前轨道给出**推荐阈值**（取最弱一层径向壳峰值的 40%）并可一键采用——各层壳峰值相差悬殊（3p `100/11.9`、4p `100/11.1/4.2`、4s `100/1.8/0.42/0.18`），任何固定默认值都必然在某些轨道上把外层壳整片切掉。下限不压到 0.02% 是因为用不到：实测"看全所有壳层"所需最低阈值是 6s 的 0.04%，而 0.04% 画出来是一团弥散巨球、教学上不如只看内几层；0.3% 已能显出 3s 的三层壳。4s/5s/6s 的推荐值会被下限顶住，此时提示行标注"（已到下限）"。
  - **三维着色不是独立开关，而是判据的推论**：画 `|ψ|²` 时函数处处非负，本就没有正负可谈（纯色）；画 `ψ`（或 `Y`）时才谈得上符号。规则三句话 —— **判据取平方 → 纯色**（按 s/p/d/f 支壳层上色）；**判据不取平方且是实数解 → 双色**（按 `sign ψ` 分 ±红/青，判据是**完整 ψ 的符号** `sign(R(r)·Y)`，故径向节点处的符号翻转也能看到）；**一切复数解 → 一律纯色**（复解的 `arg ψ` 是绕 z 轴**连续缠绕**，不是两个值，用双色编码它是错的）。
    > 原先这是一个独立的双选项开关，带来一个隐蔽问题：判据按钮只在「等值面」档显示，而电子云的颜色也由它决定 —— 等于让一个**看不见的选项**决定可见画面。改由判据派生之后两者合一，判据按钮也已提到「三维渲染」之外，电子云与等值面两档都看得见。
    > **s 轨道不特判**：1s 的 ψ 处处为正，按符号着色自然得到纯色；而 2s / 3s 有径向节点、ψ 确实变号，那时内外壳异色是物理（与 4p 三层壳同一个现象），不该因为"它是 s 轨道"就压掉。
- **量子态板块**（原在面板底部「进阶：量子态」）：**整块暂时下架**，与杂化轨道板块一起。面板上**不再挂载**那个折叠区（不是 `display:none`——否则"展开后露出半截""键盘还能 Tab 进去"这类路径依然在），智能体侧的 7 个叠加态动作也从工具清单与参数校验里一并撤销。代码与预设表全部保留：`state-editor.js` 的 `EDITOR_HIDDEN` 与 `scene-bridge.js` 的 `HIDDEN_ACTIONS` 清掉即可恢复。
- **排版口径**（全项目一致）：**变量斜体、常数与函数名正体**。ψ、Y、R、Θ、Φ、r、θ、φ、x、y、z、量子数 `n/l/m/Z`、实轨道名下标里的方向坐标 —— 斜体；`i`（虚数单位）、`e`（自然对数底）、`cos/sin`、支壳层字母（`ψ_{3p_x}` 里的 `p`）、数字与括号 —— 正体。公式里由 KaTeX 的 `\mathrm{}` / `\mathit{}` 保证；面板标签、顶栏符号与三张 2D 图的 canvas 文字里由显式标记保证（canvas 那一路见 `charts.js` 的 `fillMath`，它按段切换 `ctx.font` 逐段画）。
- **◇ 节面**（三维卡片右上角）：把节点公式变成**可点亮、可数的几何对象** —— 径向节面画成以核为中心的球壳（青色线框）、角度节面画成过核的**半透明填充面**（θ 方向的锥面、φ 方向的平面；θ=90° 的退化锥就是 xy 平面，按平面画）。画布左下角的标签写的是**当前轨道真有几种节面**（如 `径向节面 ×1 + 角度节面 ×1高亮`、`角度节面 ×2高亮`），并且**随轨道实时更新** —— 数是 `n−l−1` 与 `l`，与公式区的节点计数对得上。切到球谐档时径向节面会被移除（那一档画的是半径 1 的角度曲面，套娃球不在其中），标签随之只剩角度节面。
- **波函数实数解 / 复数解** 双模式：
  - 实数解 → 经典"瓣状"轨道（p_z、p_x、d_xy、d_z²…），**按化学名逐个选**，不出现 `m`。
  - 复数解 → 密度绕 z 轴对称的"环/锥面"，**按 `m` 选**（`m` 在这里名副其实：它是 `L̂z` 的本征值指标）。
- **多维2D视图**（手绘 Canvas，无图表依赖）：
  - 径向曲线：`R(r) / R(r)² / D(r)` 多选叠加，各自按峰值归一化。**只有这三个量**：`D(r) ≥ 0` 恒成立，再平方不改变极值点与零点，`D(r)²` 没有独立的物理含义（知识库条目同样只讲这三个，界面与讲解里都不出现它）。
  - 角度部分的两个因子：把分离变量的第二步 `Y(θ,φ) = Θ(θ)·Φ(φ)` 画出来——**左 Θ、右 Φ、中间一个「×」**，底部给出 `max|Θ| × max|Φ| = max|Y|` 的真实数字（3p_z：`1.225 × 0.399 = 0.489`）。两因子**各自归一化**（`∫|Θ|²sinθdθ = 1`、`∫|Φ|²dφ = 1`），故乘积逐点等于 `Y`，那行数字是恒等式而非示意。Θ 画在 xz 平面（极角自 **+z** 起）、Φ 画在 xy 平面（自 **+x** 起），基准不同故各自标注，并用虚线标出**角节面所在的角度**（`θ=55°`、`φ=…`）。复数解档下 `|Φ|` 是常数（**一个圆**）、下标为 `m`；实数解档标 `Φ_{±m}`，公式区并写出它**由两个复解组合而来**（`Φ_{±m} = (1/√2)(Φ_{+m} + Φ_{−m})`）。着色与三维**同源**（由判据派生的同一条规则），不再是一个需要单独设置的开关。
  - **截面**：`xy / xz / yz` 平面，三种模式 —— **`|ψ|²`**（按该点密度填色）/ **`ψ`**（按该点相位填色：实数解只有 0 与 π 两种色即正负，复数解绕原点一周走完整圈）/ **无填色等高线**（8 层对数间距、数值标注在线上、白线标出节面 ψ=0）。
    - 前两档会叠一条**白色虚线 = 当前等值面对应的那条等值线**：三维里那个面，在截面上就是这条线 —— "阈值调到多少、三维缩到哪里"由此可以在两张图之间对上号。阈值换算走与三维**同一个**出口（`OM.isoLevelAbs`）。
    - 恰为节面时（如 3p_y 的 xz 面）整面涂**一个纯色**并给出提示 —— 原先照常按相位上色，而那里 ψ ≡ 0、相位是数值零的辐角（纯噪声），会画出一整片看着"有结构"的随机颜色。
    - **球谐档下整张截面卡收起**——这张图画的始终是**含径向的完整 ψ**，而球谐档的三维画的是 `Y`，只改标签会变成"写着 Y、画的是 ψ"。
- **公式展示**：KaTeX 实时渲染当前波函数的数学表达式（代入具体 n/l/m 与归一化系数），**只给 5 行**（R / Φ / Θ / Y / ψ）——归一化常数、拉盖尔多项式乃至中间记号 ρ 一律**代入**到 R、Θ 两行里（整行只含 r、Z、a₀），不再单列成行；下标连写（`\psi_{322}`、`\Theta_{22}`）；`P_l^m(cosθ)` **展开为显式多项式**（如 `P_1^1 = -sinθ`）。
- **交互**：拖拽旋转、滚轮/双指缩放、右键（或 Shift+拖）平移、自动旋转、复位；桌面 / 平板 / 手机响应式自适配。
  - 旋转由**四元数轨道控制器**驱动：偏航绕**相机自身 Y（屏幕竖直）**、俯仰绕**相机自身 X（屏幕水平）**，均为相机局部系四元数相乘，不经过欧拉角，**从原理上避免万向节锁**，且允许自由翻滚（无极点限位）。
    > 偏航刻意**不用世界 Z 轴**：若用世界 Z，当视线俯到极点附近时世界 Z 与视线重合，"左右拖"会退化成绕视线的滚转，用户会感觉方向反了；改用局部 Y 后，任何朝向下左右拖都绕屏幕竖直轴转，方向始终一致。

## 🚀 如何运行

**方式一（推荐，离线）**：直接双击打开 `index.html`。
项目把依赖（Three.js / KaTeX）本地化到 `libs/` 并采用**全局构建**，因此 `file://` 双击即可离线运行，无需联网、无需服务器。

**方式二（可选）**：用本地静态服务器打开，便于用开发者工具调试：

```bash
cd H5
python -m http.server 8000
# 浏览器访问 http://localhost:8000
```

> 说明：若改用 ES Module 版本的 Three.js，则必须通过服务器访问（`file://` 下模块会被 CORS 拦截）；本工具刻意选用全局构建以支持双击离线运行。

## 🤖 教学智能体（可选）

右下角悬浮球打开侧边抽屉。它不是聊天框：**能感知你此刻在看哪个轨道，也能动手把话演示出来**。

- **唯一的"手"是受控动作词汇表**（三十余个动作，每个绑定一个知识点）。模型输出不可信，所有改动都要过类型/范围校验、夹紧与限流；它拿不到任何直接操作 DOM / 渲染器的口子。
- **数值一律程序算**。节点数、峰值半径、能级、期望值全部走 `math.js` / `observables.js` 的确定性求值，模型只组织语言，结构上消除数值幻觉。
- **演示排成分镜队列**：入队 + 立即返回，走一步停下等使用者点「下一步」（也可连播 / 中途「⏸ 逐步」就地刹住 / 退回去重看）。每步执行前存一份完整状态快照，「上一步」据此精确还原。
- **演示可重播、可整改、可引用、可收藏**：每条演示是一份带编号的记录（见下表"演示记录"一行）。动作气泡每行有「引用」，写入可寻址的 `演示 #N 的第 M 步`，学生提整改意见时不必复述"那个演示的第三步是哪个"；气泡末尾另有「☆ 收藏」——把**步骤清单**存进本机 `localStorage`，跨刷新、跨会话（记录本身是易失的，收藏才是持久的载体），在「会话」页里点一下即可重播。
- **讲到页面底部的图表时自动弹浮窗**，讲完自动收起（浮窗非模态、靠右停靠，不遮挡三维视图）。
- **对话可以整理**：分支树（编辑提问即分叉，分叉处有可点的分支切换片）、多会话、复制原文、重答、另起分支；刷新后回到原来的位置。
- **教学闭环**：出题（双通道出题引擎 + 自校验）、错因诊断（先给"可视化诊断动作"揭示错误根源，而不是直接报答案）、费曼式复述评估、掌握度追踪与推荐、主动服务。
- **BYOK**：密钥只存本机 `localStorage`、只发往使用者自己填的接入点。未配置密钥时可视化与内置演示脚本（零 token 回放）全部可用。

## 🧮 物理与数学约定

- 玻尔半径 `a₀ = 1`（长度以 a₀ 为单位）；球坐标 `(r, θ, φ)`，θ 为与 z 轴的极角（**z 为量化轴**，三维中竖直）。
- 波函数 `ψ_{n,l,m} = R_{n,l}(r) · Y_{l,m}(θ, φ)`，已归一化（`∫|ψ|²dV = 1`）。
- **径向**：`R_{n,l}` 含广义拉盖尔多项式 `L_{n-l-1}^{2l+1}`；`D(r) = r²R(r)²` 为径向分布函数。
- **球谐**：复模式 `Y_l^m = N·P_l^{|m|}(cosθ)·e^{imφ}`（**含** Condon–Shortley 相因子 `(-1)^m`）；实模式由复球谐组合得到 cos/sin(mφ) 型实轨道，而**组合系数恰好把该相因子约掉**，所以实解的 Θ 不带它 —— 这两档若混用，`Y = Θ·Φ` 的逐点恒等式就会差一个 `(-1)^{|m|}`。Φ 的下标据此分档：复解 `Φ_m = (1/√(2π))·e^{imφ}`；实解 `Φ_{±m} = (1/√2)(Φ_{+m} + Φ_{−m}) = (1/√π)cos(mφ)`（sin 型同理，系数为 `1/(i√2)`）—— 实解不是"另一个量子数的解"，而是 ±m 两个复解的线性组合，下标与组合关系都写在公式区里。
- 数学均为纯 JS 递推实现（拉盖尔/勒让德/球谐、复数运算），n≤6 时阶乘不越界、float64 精确，故无需 NumPy/Pyodide（后者 ~15MB、移动端首屏慢）。

## ⚙️ 关键技术决策

| 决策 | 原因 |
|---|---|
| 纯 JS 手写数学（弃 NumPy/Pyodide） | 移动端秒开；波函数所需数学仅需少量递推，精确且轻量 |
| Three.js r147 全局构建 | r148 起非模块 `OrbitControls` 被移除，且新版为 ES Module（`file://` 下被 CORS 拦截）；全局构建可双击离线运行 |
| **四元数轨道控制器**（不用 `OrbitControls`） | `OrbitControls` 用球坐标 + up 向量描述朝向，视线与 up 平行时存在万向节锁；改为四元数累积旋转（偏航、俯仰都取相机局部轴：Y 轴对应屏幕竖直、X 轴对应屏幕水平），全程不经欧拉角，无奇异点，另加 ±Z 极点软限位防止翻过头 |
| 等值面用 marching **tetrahedra**（非 cubes） | 免去 256×16 巨型查找表，规则简单、必定正确；三角形略多，用较高网格分辨率补偿 |
| 等值面重建走**主线程时间切片**（`js/sched.js`），不引入 Worker | 一次状态变更原本是 200–700ms 的**同步块**（场填充 ~100ms + 抽面 40–70ms + 焊接/平滑 70–100ms，细颈补片一段就 240–600ms），期间自动旋转停住、按钮点不动、拖滑块不跟手。改为把每个阶段拆成"一次推进一层 k / 一段区间"，由**既有的渲染循环**（`animate`）按每帧 8ms 预算批 —— 相机阻尼与自动旋转照常每帧推进，看到的是"画面在动、结果慢慢长出来"。**为什么不用 Worker**：本项目要求 `file://` 双击即用，而实测该协议下普通 worker 文件被 `SecurityError` 挡下，Blob worker 里 `importScripts('file://…/math.js')` 报 `NetworkError` —— worker 源码必须完全自包含，等于把物理计算复制一份。实测：一次完整重建（3p_z 4%，带细颈补片）期间最大帧间隔从 200–600ms 降到 33ms，`longtask` 归零 |
| 切片只改"**什么时候算**"，不改"算什么" | 每个阶段都是纯写入且跨片无依赖：唯一跨片状态是场峰值的最大值归约；抽取的单元彼此独立、按 k 升序拼接即与原顺序相同；焊接必须按升序**共用同一个 Map**（顶点 id 按首次出现顺序分配，分片各建一个会让接缝处的重复顶点合不上）。验收判据是**逐位一致** —— 粗面与细颈补片的顶点数、三角形数、位置/法线的 32 位滚动哈希与改动前完全相同（8 个用例 × 2 条路径 = 16/16）。★ 顶点数会被"凑巧一样"蒙混过去，而各分量求和又会在**中心对称**的曲面上大幅抵消（实测 6 个用例里 4 个回到 0），故用逐元素滚动哈希 |
| 拖动滑块时降到 40³ 且**不做局部精细化** | 全分辨率一次重建即使切了片也要跨十几帧才长出来，拖着滑块时画面一直落在上一帧的旧面上。拖动中改用 40³（单元数约为全档的 1/5）。**只认真人事件**（`e.isTrusted`）：程序化写 `value` 同样派发 `input` 而不会再触发 `change`，认了它标志就会一直挂着、细颈补片从此不出现；另有一个 400ms 兜底定时器，即便 `change` 没来（方向键、程序化写入）也能自愈。实测拖动中帧间隔最大 17ms（≈58fps），且画面仍以约 10 次/秒持续更新 |
| 拖动中重算用**节流**，不用防抖 | 防抖的语义是"等输入停下来再说"，而拖动时每 16–45ms 就有一次 `input`，定时器被一再推后、**一次都不会触发** —— 整个拖动过程中画面纹丝不动（实测：当时帧率漂亮得可疑，一查根本没在算，分辨率采样全程停在拖动前的值）。节流保证每 100ms 至少算一次 |
| 拖动中后来的请求**排队覆盖**，不取消在飞的那次 | 每个 `input` 都来一次请求，若每次都取消，一次重建（宽约 100ms）永远跑不完 —— 用户在整个拖动中一次都看不到新面。排队覆盖保证"总有一次能跑完并换上去"。非拖动时仍照旧取消：那是一次离散变更，旧结果确实没人要，等它跑完只是白等 |
| 拖动中**不重画 2D 图与公式** | 它们是同步的一整块（三张 Canvas + KaTeX），而拖动时用户盯的是三维视图。实测单独把拖动中的帧间隔从 p95 33ms 降到 p95 17ms —— 三维的流畅正是被这几张图拖垮的。松手后立刻以全档重算一次，图上不会有残留的旧读数 |
| 粗面与细颈补片**一起上屏** | 粗面抽取时按 maskR 把节点球内的单元挖掉、留给细网格补，所以**粗面本身是不完整的**。同步版两步同帧完成、看不出这个中间态；切片后细颈要跨约 1.2 秒，只换粗面等于在画面上留一个**洞**（用户报的"渲染的时候部分等值面会消失"）。实测负对照连拍：中间 4 帧少了 6.5% 的曲面像素（内层壳整片消失），改为"一起就绪才提交"后全程恒定（偏差 0.2%，全在抗锯齿范围内） |
| 缓存键含**网格分辨率**，并且"这份场是什么"要显式记下来 | 拖动中与松手后是两张不同粗细的网格，键里不带分辨率，松手后就会命中缓存、把那张 40³ 的粗场赖在画面上不走（与当初"Z 漏出缓存键"是同一个错）。更隐蔽的一条：**切片之前"缓存场就是当前配置的场"这个前提是自动成立的**，切片之后"准备"与"发布"之间隔着几十帧，一次被打断的重建会让模块里留着**上一套配置**的场，而调用方以为它是最新的 —— 实测表现为"换了轨道、盒子与峰值却对不上任何一条轨道"（3d_z² 的画面里发布的是 3p_z 的场）。故场一起发布"参数指纹"，复用前必须核对；细颈阶段顶替/还原那套场量时，指纹也一并存还 |
| 细网格分辨率**从估值往上搜索** | `res ≈ 5·radius/gap` 只保证**核附近**的格距够细，而"不越界到外层壳"那道关管的是盒子**最外层**的格距（渐变网格外疏内密，两者能差好几倍）。拿核的估值去过外层的闸，低阈值下必然越界 —— 表现就是"阈值一低就不精细化了"：实测 5f 在 3% 有精细化、降到 1% 就没了，而它只需把 res 从 68 提到 88 就能过。改为从估值起往上试到两道关都过为止（上限 112³，代价有界：最多几十次纯算术比较） |
| 「连续调整期间先跳过细颈、停下来再补」的重试必须有**显式入口** | 这条重试原先靠"距上次重建超过 450ms"来判断，而重试定时器是 `450+70=520ms`：一次 100ms 的重建让重试恰好落在"上次重建结束 + 420ms"，永远差 30ms 过不了关 → **细颈补片永远不出现**，而且它自己刷新时间戳，形成**不动的循环**（实测：3.5 秒内一次都没出现，粗网格顶点数正好等于"没挖掉节点球内单元"的那个值）。改为给重试一个显式标记绕开该判据；这条判据本身也改成"连**开始**时刻一起记"，否则一个正在跑的重建会被当成"太久没动了" |
| 三维画布高度由 JS 按视口算（`layout.js`），不写死 | 写死 `clamp(280px, 44vh, 470px)` 时，"高度=窗口高"这个直觉等式从不成立——顶端还有顶栏、卡片标题、内边距。改为量出画布顶端在文档中的位置，用 `视口可见高 − 该位置 − 余量` 下发 CSS 变量，移动端读 `visualViewport` 以正确处理地址栏收放 |
| 相机取景由 `fov + aspect` 共同决定，不用"距离 = 尺度 × 常数" | 固定倍数下留白会随画布宽高比漂移：宽扁画布上轨道顶满上下边缘，竖屏还会被左右切掉。改用"需要容纳的半尺寸 ÷ tan(fov/2)"并同时校验水平方向，任何画布比例下留白一致、永不裁切 |
| 智能体动作**排成分镜队列、由用户逐步确认**（可前进 / 回退 / 连播 / 重播） | 一次下发的动作若同步 tight-loop 执行，十几个动作会在几十毫秒内全落地，学生只看到最终画面、中间每步都"闪"过去，演示等于没演示；而固定时长的自动连播又不由学生掌握节奏。改为"入队 + 立即返回 + 闸门等待"：工具不再阻塞对话循环，节奏完全交给学生。**每步执行前存一份完整状态快照**，「上一步」据此精确还原——反向执行动作做不到这件事，因为动作带副作用（例如 `setQuantumNumbers` 会顺手退出叠加态） |
| 闸门放在"执行之前"而不是"执行之后" | 两种写法在逐步前进时完全等价，但"先闸门"让循环可以从**任意一步**恢复：演示播完之后点「上一步」，只需重起循环并标记"先停闸门"，就能退回去重看而不立刻执行 |
| 演示预设可增删（存 localStorage） | 内置预设表达不了系数不等的非等价组合。智能体现场构造的示意系数对话一过就没了，存成预设后学生可一键复现、反复对照——从"一次回答"变成"留在工具里的教具" |
| 演示记录**独立于播放队列**存在 | 演示原先只活在队列里，而下一次 `applySceneActions` 一进来就清空队列 —— "刚播完的那条""前几轮对话里那条"在数据结构上直接消失，既重播不了也整改不了（实测：整改工具对**每一步**都报"只能修改尚未执行的步骤"，因为播完后待执行下标等于总步数）。改为 `demoId → 完整步骤清单` 单独记一份，队列只是它的一次放映；刷新后由**对话历史**重建（每次工具调用的参数与回执就是全部信息），不需要额外持久化。演示编号必须与现有记录比对后再取（用递增计数器会在刷新后撞号，把新步骤追加进旧记录 —— 实测一条 8 步的演示变成 16 步） |
| 演示整改区分「就地改」与「整份重载」 | 演示正暂停、要改的是**后面还没播**的步骤 → 就地改，学生不必重看已看过的（也保住「上一步」的快照链）；演示**已经播完**或要改的是**已经看过**的步骤 → 取出完整清单、改一处、整份重放并**快进到改动点停下**（快进段照常执行、照常存快照，只是不留停顿——跳过执行会让到达改动点时的画面是错的）。两条路都不能少：前者是"接着讲"，后者是"回头改" |
| `focusChart` 由程序提到批首（**换轨道时除外**） | 实测同一句提问，模型两次给出相反的 `focusChart` / `showRadial` 顺序；排在图变化之后时学生"听着讲图、图却在变、浮窗还没开"。顺序不能寄希望于模型每次都排对，就在提交动作前用代码规范化（`target:'none'` 的收窗动作排除，否则会打乱脚本里"收窗 + 落参考球"的顺序）。**但"提到批首"只在它前面确实是"改这两张图"的动作时才做**：若同批还要换轨道，浮窗放大的是**当前**那张图，先放大就会让学生看到上一个轨道的图 —— 这种情形要求"先换轨道、再 `focusChart`"，写进智能体的硬性约定（程序无从判断模型的意图，代劳不了） |
| `manual` 是"这一次调用"的属性，不是全局开关 | `applySequence({auto:true})` 原先直接写 `manual=false` 且不恢复，界面上又没有按钮能改回来 —— 跑过一次内置演示后，之后所有演示都只能连播。改为 `try/finally` 保存恢复（`runQueue` 里任何一条提前 return 都会跳过普通语句），并补上「⏸ 逐步」出口 |
| 停留判据是 `!manual`，`paced` 一律传 `true` | 曾经手动入队时传 `paced=false`（"手动模式不需要 pacing"读起来完全说得通），但它是在**循环开始时**定死的：学生中途点「连续播放」后，剩下的步骤会**一个停顿都没有地瞬间播完**（实测 0.6 秒内 5 步全过）。停留条件本来就只在 `!manual` 时生效，所以 `paced` 不该由入队时的模式决定 |
| 面板高度从三维卡片**单向**推导 | 面板内容比三维视图高时会把整行栅格撑高、把下面的公式与图表往下推，而 3D 画布高度是按"窗口可见高度"算死的，右侧便多出一大截空白。改为量出三维卡片高度下发 `--panel-h`。**单向是防自激的关键**：`.viewer-card` 带 `align-self: start`，不会被同一行更高的面板拉伸，所以"面板 → 行高 → 三维卡片"这条回路在结构上不存在。单列布局（≤1024px）下移除该变量 |
| 对话按**分支树**存，编辑提问 = 从那里分叉 | 分支不是"创建"而是**移动一个指针**（`parent` 单亲指针 + 一个 `leaf`），投影成消息列表是**纯函数**——于是"切回旧分支时后续消息还在"由"节点从不删除、只有 leaf 在动"天然保证，不需要复制任何字节。分支切换片只在**当前路径**上出现，所以「会话」页另给一份**全局分支点清单**：切到另一条分支后，原来那个分叉点就不在路径上了，只靠消息区会找不到回去的路 |
| 复制取**存档源文本**，不从 DOM 反解析 | DOM 里是 KaTeX 渲染后的 HTML，`textContent` 会把 `$\frac{1}{2}$` 变成 `21`（分子分母粘连），公式源码彻底丢失。另：`file://` 不是 secure context，`navigator.clipboard` 不可用，必须走隐藏 textarea + `execCommand` 降级 |
| 智能体**绝不静默失败**：必须读 `finish_reason`，空正文也要有交代 | 输出上限被触发时，早期版本把 `finish_reason` 解析出来却没有任何一处读它，界面上便只剩一个**空白气泡**——用户只会觉得工具坏了。现在：截断即自动续写（有次数上限）并提示；正文为空时区分 `length` / `tool_calls` / 其他三种成因，并附上 `finish_reason` 与 token 用量作为证据 |
| 流式请求显式索取 `usage`（`stream_options.include_usage`） | 流式响应默认**不返回 usage**，没有它就只能猜"输出为什么是空的"。同时把 `stream_options` 与 `max_tokens` 做成**可降级字段**：服务端 400 报错点名了哪个字段，就自动去掉它重试一次。否则用户把输出上限填得比模型上限大一点，整个功能就直接不可用了 |
| 2D 图表手绘 Canvas | 三种图表形态各异，手绘控制力强、零依赖、与暗色主题统一 |

## 🔧 扩展指南

- **新增渲染/视图**：在对应模块（`render3d.js` / `charts.js`）加函数，并在 `main.js` 的 `updateViewer` / `updateCharts` 中调用。
- **调整颜色**：改 `math.js` 的 `SUBSHELL_COLOR`（s/p/d/f/g）；相位映射改 `phaseColor`。
- **量子数与核电荷数上限**：`index.html` 的 `nSlider` `max`（6）与 `main.js` 的 `maxL`（5）联动；`zSlider` 的 `max`（36）与 `scene-bridge.js` 里 `validate` 的 Z 范围联动 —— 改上限时这两组要各自一起改，否则会变成"界面能拖到、动作却被拒"（本轮 Z 从 6 放宽到 36 时就踩过：控件放开了、动作层还卡在旧范围）。
- **性能**：粒子数滑块控制点数；等值面网格分辨率统一走 `main.js` 的 **`currentGridRes()`**（全档 `isMobile ? 46 : 68`，拖动中降档 `isMobile ? 30 : 40`），**不要再另写一份** —— 它同时被渲染、缓存键两处使用，两处不一致就会出现"松手后粗网格赖着不走"。长任务一律经 `js/sched.js` 切片（`Sched.run({step, done, abort})`），不要新写同步重活。

## ⚠️ 已知取舍

- 等值面在网格分辨率与平滑之间折中；移动端用较低分辨率以保证流畅（见 `currentGridRes()`）。
- **局部精细化（细颈）只在满足三个条件时启用**：单一本征态、`l ≥ 1` 且**有径向节点**（`n−l−1 ≥ 1`）、细颈比粗网格单元格还窄。所以 `4f`、`5g`、`6h` 这类**最高角动量**的轨道（`n−l−1 = 0`，无径向节点）以及 `3d/4d/5d` 全都不做精细化：分界球面必须落在"两层壳之间**必然**没有曲面"的位置，否则两套网格在接缝处会露出裂缝，而这类轨道整层壳里没有这样的球面（它们的细颈出现在壳的中段，那里有曲面）。这是有意的取舍 —— 宁可让相邻瓣在低阈值下略显粘连，也不留碎三角片。
- 阈值取到**最低档**（0.3%）时，多数轨道也不做精细化：此时盒子极大（3p 到 24.7a₀、6g 到 88.9a₀），要让"细网格单元不越界到外层壳"就得把分辨率提到 158–182³（场内存 63–96MB 且抽取要数秒），代价不成比例。1% 及以上已按需自动提高分辨率。
- 复模式要看**完整一圈**的相位缠绕，用**截面卡的 `ψ` 档**（xy 平面）：三维球面受视角遮挡看到的 φ 范围有限，而截面上"绕原点一周"是字面成立的。
- 「教材对照表」（R 表 / Y 表）依赖 `assets/ref/` 下的两张表格图片；该目录未随仓库分发，
  图片缺失时面板会显示查阅指引而不是裂图（书目见根 [README](../README.md) 的「参考书目」）。
